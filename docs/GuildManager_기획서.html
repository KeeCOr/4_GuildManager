문제 정의

어떤 유저가: 방치형 성장에 만족하지 못하고, 파티 조합·장비·퀘스트 위험도를 직접 조율하고 싶은 전략 선호 게이머

어떤 상황에서: 수치가 알아서 올라가는 자동화 루프의 모바일/웹 게임을 플레이하다가, 짧은 틈새 시간(10~20분) 안에 의미 있는 전략적 판단을 내리고 싶을 때

어떤 게임적 욕구를: 자동화 루프에서는 얻기 어려운 "내가 잘한 선택이 차이를 만들었다"는 느낌과, 그 결과를 즉시 확인하며 다음 전략을 구상하는 순환 — 한 번의 파견 결정이 보상·손실·성장으로 즉시 이어지는 길드 운영의 손맛을 원한다.

주 페르소나

이름: 박수진 (33세, 대기업 마케팅 팀장)

직업: 소비재 브랜드 마케팅 팀장 (팀원 5명 관리)

현재 게임 습관: 퇴근 후 30~40분, 주말 오전 1시간. 심즈 시리즈, 스타듀 밸리, Recettear(아이템샵 경영) 등 "내가 운영하는 공간과 사람들이 성장하는" 경영·시뮬 장르를 좋아한다. 과금 부담 없이 브라우저에서 바로 실행되는 게임을 선호한다.

이 게임을 플레이하는 맥락: 퇴근 후 소파에서 노트북을 열어 "오늘 길드 상황 어떻지"를 확인하는 것이 하루의 소소한 루틴이 됐다. 용병 컨디션을 보며 "이 조합이면 이 퀘스트는 가능하겠다"는 판단이 직관적으로 나올 때 가장 만족스럽다.

기대하는 경험: 한 세션 10~20분 안에 상황 파악 → 파견 결정 → 결과 확인이 깔끔하게 끝나고, 내일 또 접속하게 만드는 "미완의 목표(다음 장비 세트 완성, 명성 500 달성)"가 항상 남아있는 구조.

핵심 루프

유저가 길드 현황(자원·용병 컨디션·임박한 퀘스트)을 파악한다
  → 퀘스트 파견 또는 장비·채용에 자원을 투자하는 결정을 내린다
  → 퀘스트 결과(성공/실패·보상·사상자)가 즉시 반영된다
  → 변한 자원과 용병 상태를 바탕으로 다음 선택을 준비하며 루프를 반복한다

MVP 가설

  1. [핵심 파견/운영 루프]가 있으면 한 판 안에서 선택 결과를 즉시 이해한 플레이어가 자발적으로 다음 판을 시작하고 1회 플레이 후 재시작률 60%를 달성할 것이다.
  2. [위험·보상 동시 표시]가 있으면 위험과 보상이 동시에 한 화면에 보여 선택 시간이 줄고 납득도가 오른다 — 주요 선택 평균 8초 이내, 결과 불만 피드백 20% 이하로 유지될 것이다.
  3. [장비 세트 보너스]가 명확하면 세트 효과가 체감될 만큼 강하게 표시되어 플레이어가 장비 조합을 적극적으로 시도하고 3판 내 서로 다른 빌드 선택률 50% 이상을 달성할 것이다.
  4. [행상인 타이머]가 있으면 한시적 방문 구조가 골드 지출 결정의 긴장감을 높여 행상인 방문 시 장비 구매율 40% 이상을 달성할 것이다.
  5. [저장 슬롯 시스템]이 있으면 3개 슬롯 분리 저장이 가능해 복수 빌드 실험 의욕이 높아지고 슬롯 2개 이상 사용 비율 30% 이상을 달성할 것이다.

소개용 핵심 메시지

GuildManager는 "수치를 쌓는 게임"이라기보다 "매 세션 최적 파견 조합을 찾아가는 게임"이다. 플레이어는 용병의 컨디션·직업·세트 장비를 보고 지금 높은 위험도 퀘스트에 도전할지, 행상인에게 장비를 업그레이드할지, 낮은 위험도 퀘스트로 안전하게 명성을 쌓을지 결정한다.

  • 좋은 파견 조합은 높은 성공률과 명성·보상으로 즉시 돌아온다.
  • 장비 세트 효과와 용병 컨디션 관리가 위험한 퀘스트를 가능하게 만든다.
  • 한 세션의 재미는 "이번 조합으로 어디까지 올라갈 수 있나"를 빠르게 판단하는 데 있다.

PR 체크리스트

  • 퀘스트 파견 → 성공/실패 판정 → 보상/손실 처리 → 루프 반복이 정상 동작한다.
  • 장비 세트 효과가 2세트·3세트 각각 정확히 발동하고 중복 적용 이상이 없다.
  • 행상인 방문 타이머가 탭 비활성화 후 복귀 시에도 정확히 유지된다.
  • 던전 발생 확률 판정과 층 입장 조건이 퀘스트 티어에 따라 올바르게 작동한다.
  • beforeunload 시 동기 저장으로 마지막 상태가 손실되지 않는다.
  • 예상 성공률이 파견 조합 변경마다 즉시 재계산되어 표시된다.
  • 문서 이미지와 실제 현재 구현 화면이 크게 어긋나지 않는다.

🎮 게임플레이 / 핵심 기능

우선순위제안기대 효과
높음퀘스트 결과 화면에 "다음 세션 개선 힌트" 패널 추가 — 실패 원인(컨디션 부족, 장비 미스매치, 속성 불일치)과 해결 방향을 1~2줄로 즉시 표시결과 불만 피드백 감소 + 2회차 진입률 KPI(55%) 달성 가속
높음파견 조합 화면에서 예상 성공률을 실시간 수치(%)로 표시 — 용병·장비·속성 가중치를 합산한 단일 수치로 제공주요 선택 평균 8초 이내 KPI 달성, 선택에 대한 납득도 향상
중간던전 입장 시 "이번 층 예상 보상 vs 위험 용병" 요약 카드 표시 — 현재 파티 구성 기준 생존 예측치와 기대 골드를 나란히 비교던전 이탈률 감소 및 고위험 선택에 대한 자발적 도전 유도
중간행상인 방문 중 장비 비교 오버레이 — 현재 장착 장비와 구매 후보 장비의 스탯 차이를 +/- 형태로 즉시 표시행상인 구매율 KPI(40%) 달성 지원 및 구매 후 후회 감소
낮음용병 "컨디션 회복 예상 타이머" 표시 — 부상·피로 상태 용병이 언제 복귀하는지 세션 시작 화면에서 확인 가능하도록세션 시작 시 운영 계획 수립 속도 향상

🖥️ UX / UI

  • 세션 시작 정보 밀도 과부하: 길드 현황·퀘스트 목록·행상인 타이머가 동시에 표시될 경우 시선 분산 문제 — 중요도 기준으로 "지금 당장 해야 할 것(퀘스트 마감 임박, 행상인 출발 임박)"을 화면 상단 알림 배너로 분리하고 나머지는 접을 수 있는 패널로 이동한다.
  • 세트 효과 미완성 진행도 시각화 부재: 장비 세트가 1/3, 2/3 완성된 상태에서 어떤 아이템이 필요한지 MercCard에서 바로 보이지 않아 목표 지향적 구매가 어려움 — 카드 하단에 세트 진행 도트(●●○)와 다음 효과 툴팁을 추가한다.
  • 퀘스트 위험도 색상 코드 부재: 현재 위험도 표시가 텍스트 기반일 경우 스캔 속도가 느림 — 저/중/고위험에 녹색/노란색/빨간색 레이블 배경을 적용해 2초 이내 시각적 분류가 가능하도록 개선한다.
  • 파견 전 결과 예측 정보 부재: 용병 카드 호버 시 해당 용병이 조합에 추가됐을 때 예상 성공률 변화를 즉시 표시 — "쓰기 전에 결과를 안다"는 신뢰를 준다.

💰 수익화 전략

  • 프리미엄 세이브 슬롯 확장: 기본 3슬롯 외 추가 슬롯(4~6번)을 소액 결제로 해금 — 멀티 빌드 실험을 즐기는 핵심 페르소나(김재훈)의 지불 의향과 일치하며, 게임 밸런스를 해치지 않는 편의 과금 구조.
  • 프리미엄 장비 스킨 팩: A/S급 장비의 시각적 대안 외형을 패키지 판매 — 스탯 변화 없이 외형만 바꾸는 방식으로 페이투윈 부담 없이 수집 욕구 자극.
  • 광고 제거 + 콘텐츠 번들: 광고 배너 노출 기반 무료 플레이 후, 일정 명성 도달 시 "프리미엄 패스(광고 제거 + 전용 용병 1인 + 세트 아이템 1종)" 번들 제안 — D7 리텐션 도달 유저 대상 전환율 극대화.

📦 콘텐츠 확장

  • 단기(1~2개월): 직업별 전용 패시브 스킬 트리 추가 — 용병이 퀘스트를 반복 수행하면 직업 특화 스킬(전사: 방어막, 도적: 연속 함정 해제, 마법사: 속성 연쇄)을 해금하는 미니 성장 트리로 반복 플레이 동기 강화.
  • 중기(3~6개월): 계절 이벤트 퀘스트 사이클 — 4주 단위로 테마 퀘스트(겨울 눈보라 생존전, 수확제 호위, 마왕 출몰 비상 소집)와 한정 세트 아이템 등장으로 D30 리텐션 지점 붙잡기.

⚙️ 기술적 개선

  • 성공률 계산 캐싱: 파견 조합 변경 시마다 성공률을 재계산하는 구조면 용병 수 증가 시 UI 응답 지연 발생 — 조합 변경 이벤트에 메모이제이션(useMemo)을 적용해 동일 입력에 대한 중복 계산 제거.
  • 자동저장 충돌 방지: 디바운스 1초 자동저장 중 브라우저 탭이 닫히면 마지막 상태가 손실될 수 있음 — beforeunload 이벤트에서 동기 저장(localStorage.setItem) 강제 실행으로 세이브 손실 리스크 제거.
  • 퀘스트 타이머 드리프트 보정: useGameLoop.ts의 인터벌 기반 타이머는 탭 비활성화 시 브라우저 스로틀링으로 실제 경과 시간과 어긋날 수 있음 — 인터벌 콜백에서 Date.now() 기준 실제 경과 시간을 계산해 판정 기준으로 사용하도록 변경.
  • 행상인 타이머 정확도: 탭 비활성화 후 복귀 시 남은 시간이 올바르게 표시되는지 확인 — 페이지 가시성 변경(visibilitychange) 이벤트에서 타이머 기준 시간을 재동기화하는 로직 추가.
