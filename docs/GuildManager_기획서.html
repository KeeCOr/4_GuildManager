Hustle Castle룸 선택 → 거주민 배치 → 생산/훈련 피드백룸 배치·상태 변화는 수치 로그가 아니라 성(城) 안에서 눈으로 보이게 만들어야 한다

핵심 루프

계약 파견 완료 → 참가자별 귀환 원인·상태 확인 → 3가지 활동 중 하나 선택
  → 용병·룸 피드백 확인 → 다시 파견

구현 상세 (실제 반영 기준)

  • 결정론적 에피소드 ID: ${questId}:${completesAt} 형식(src/utils/returnEpisode.ts의 generateReturnEpisode)으로, 동일 파견에 대해 항상 같은 ID가 생성된다.
  • 큐잉 시점: 일반 완료(processCompletions)와 수정구 즉시완료 경로 모두에서 에피소드가 생성되어 enqueueReturnEpisode로 대기열에 쌓인다. 두 경로 모두 결과 로그 모달(showLogModal)을 먼저 띄우도록 setShowQuestModal(false) → setShowLogModal(true) 순서를 유지하며, 귀환 에피소드 모달은 결과 로그를 포함한 다른 모든 모달이 닫힌 뒤에만(returnEpisodeBlockingUIOpen이 거짓일 때) 열린다.
  • 한 번에 하나씩: returnEpisodeState.pending[0]만 화면에 노출되므로 에피소드는 항상 순서대로 하나씩만 등장한다.
  • 참가자 카드: 초상화(MercAvatar), 이름, 귀환 상태(대기중/부상/영혼) 배지를 가진 명명된 카드로 표시된다.
  • 원인 서술(cause): 성공 시 생존자(없으면 전체 참가자) 중 전투력이 가장 높은 기여자를, 실패 시 생존자 중 HP·컨디션이 가장 낮은 부상자를(생존자가 없으면 전투력이 가장 높은 전사자를) 결정론적으로 골라 "OOO의 활약으로 임무를 성공적으로 마쳤다" / "OOO의 부상으로 임무는 실패로 끝났다" 식 문장을 만든다.
  • 3가지 선택지(생존자 전원 대상, 영혼/사망 용병은 완전히 제외):
    • 축하 연회(식당) — 사기 +8, 호감도 +4
    • 작전 복기(훈련소) — 경험치 +45, 임계치를 넘으면 통상적인 레벨업 처리(레벨·다음 경험치량·전투력·함정해제·스탯 동반 상승)
    • 치료와 휴식(길드마스터룸, 의무실 비주얼 앵커) — HP +35, 컨디션 +20, 부상 상태였던 용병은 대기중으로 복귀
  • 룸 시스템 재사용: 새 통화나 새 룸 시스템을 만들지 않았다. 기존 roomAgents(대기중 용병 슬롯 표시)에 임시 행동 텍스트 오버라이드를 추가하고, 기존 장면 포커스(focusRoom/SCENE_FOCUS)를 재사용해 해당 룸을 화면에서 강조하는 방식으로만 구현했다.
  • 세이브 호환성: SaveSlotData.returnEpisodeState는 optional 필드다. normalizeReturnEpisodeState가 손상되거나 중복된 레거시 데이터를 정상화하고, 안정적인 에피소드 ID와 처리 완료 ID 원장(processed ledger)이 재적용을 막아 멱등성을 보장한다. 원장은 최대 200건으로 잘린다.

재미가 만들어지는 지점

  • 인정(recognition): "누가 왜 이렇게 됐는지"가 이름으로 서술되어, 결과가 숫자가 아니라 이야기로 남는다.
  • 의미 있지만 가벼운 선택: 사기/호감도, 성장(경험치), 회복(HP/컨디션)이라는 서로 다른 3가지 회복·성장 축 중 하나를 고르게 해, 매번 고민할 거리는 주되 분석 부담은 낮춘다.
  • 눈에 보이는 성(城)의 반응: 선택한 활동에 따라 룸 슬롯 텍스트가 바뀌고 장면이 해당 룸으로 포커스되어, 선택이 성 안에서 실제로 일어난 일처럼 느껴진다.
  • 낮은 마찰의 1클릭 CTA: 44px 높이의 "적용" 버튼 하나로 즉시 완결된다.
  • 짧은 피드백 배지: 우측 상단에 활동명·대상·보상 요약이 잠깐 떠 확인 비용이 거의 없다.

이 다섯 가지가 합쳐져 "이번 귀환은 어떻게 마무리할까"라는 짧은 기대감을 만들고, 그 기대감이 결과 확인 → 선택 → 다음 파견으로 이어지는 루프의 재진입 동기가 된다. 그라인드를 추가하지 않으면서도 매 귀환을 한 번 더 들여다보게 만드는 것이 핵심이다.

실패/악용 시나리오와 안전장치

  • 더블클릭·중복 저장: resolvingReturnEpisodeIdsRef가 처리 중인 에피소드 ID를 즉시 잠그고, processedIds 원장이 이미 처리된 ID의 재적용을 막아 이중 보상이 불가능하다.
  • 사망 참가자 제외: 상태가 영혼인 용병은 어떤 선택지를 골라도 효과가 적용되지 않고 피드백 대상에서도 제외된다.
  • 레거시 데이터 누락: 구버전 세이브에 returnEpisodeState가 없으면 normalizeReturnEpisodeState가 빈 상태(대기열 없음, 처리 원장 없음)로 정규화한다.
  • 모달 우선순위: 결과 로그 모달을 포함한 다른 모달이 열려 있으면 귀환 에피소드 모달은 뜨지 않아 겹침이 없다.
  • 무작위 승급 없음: 작전 복기의 레벨업은 고정된 경험치 +45만 반영하며 임의의 확률 보정은 없다.
  • 큐 순서 보존: 여러 계약이 동시에 완료돼도 각 에피소드는 발생 순서대로 대기열에 쌓이고 그 순서대로 소비된다.
